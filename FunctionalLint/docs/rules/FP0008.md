# FP0008: Mutable collection types are not allowed in signatures

`IList<T>`, `ICollection<T>`, `IDictionary<,>`, `ISet<T>`, the non-generic `IList` and `IDictionary`, and every concrete type from FP0005 are reported in parameters, return types, fields and properties. Nested types count too, so `Task<List<T>>` is caught.

Overrides and interface implementations are skipped, because they can't choose their signature.

On a field, the message says the collection "can be changed by any code that can see it", since a field has no callers.

## Why

A signature is a promise. A mutable collection in it lets either side change what the other holds.

## Instead

Before:

```csharp
public static decimal Total(IList<Line> lines) => ...;
public static List<int> Ids(IEnumerable<Order> orders) => ...;
```

After:

```csharp
public static decimal Total(IReadOnlyList<Line> lines) => ...;
public static ImmutableArray<int> Ids(IEnumerable<Order> orders) => ...;
```

## Auto-fix

Yes. `IList<T>` and `List<T>` become `IReadOnlyList<T>`; `ICollection<T>` becomes `IReadOnlyCollection<T>`; `IDictionary<,>` and `Dictionary<,>` become `IReadOnlyDictionary<,>`; `ISet<T>` and `HashSet<T>` become `IReadOnlySet<T>`.

Callers passing a list still compile. If the method body changed the collection, the compiler now points at that line.

Queues, stacks, `StringBuilder` and the like have no read-only interface, so they're left for you.
