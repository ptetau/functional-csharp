# FP0015: Calls that throw are not allowed

FP0007 stops the `throw` keyword. This rule stops the common library calls that throw anyway:

| Call | Throws when | Use instead |
|---|---|---|
| `First`, `Last` | nothing matches | `FirstOrDefault`, or a list pattern: `xs is [var first, ..]` |
| `Single`, `SingleOrDefault` | there's more than one match | a list pattern: `xs is [var only]` |
| `ElementAt` | the index is out of range | `ElementAtOrDefault` |
| `Min`, `Max`, `Average` of numbers | the sequence is empty | `xs.DefaultIfEmpty(0).Max()` |
| `Aggregate` without a seed | the sequence is empty | `Aggregate` with a seed |
| `ToDictionary`, `ToImmutableDictionary` | two items have the same key | `GroupBy` on the key first, or `ToLookup` |
| `ImmutableDictionary.Add` | the key is there with a different value | `SetItem` |
| `dictionary[key]` | the key is missing | `TryGetValue` or `GetValueOrDefault` |
| `int.Parse`, `DateOnly.Parse`, `Enum.Parse`... | the text isn't valid | `TryParse` |
| `Convert.ToInt32(string)` and friends | the text isn't valid | the target type's `TryParse` |

Three operators are reported too:
- **Casts that can fail:** a downcast (`(Circle)shape`), unboxing (`(int)boxed`), or a nullable to its value (`(int)maybe`). Use a pattern: `shape is Circle circle`. Numeric and enum casts don't throw, and neither do `as`, patterns or upcasts.
- **Integer and decimal division and remainder** (`a / b`, `a % b`) when `b` may be 0. A non-zero constant can't be, nor can `Math.Max(1, n)` or `Math.Clamp(n, 1, ...)` (directly or through a local), nor a value checked first: `b != 0 ? a / b : 0`, `b > 0 && ...`, `b is not 0`, or a switch arm's `when b != 0`. Floating-point division gives infinity or NaN instead of throwing, so it isn't reported.
- **Indexing an array, list or string** (`xs[i]`, `xs[0]`, `xs[^1]`) when the index may be out of range. Use a list pattern (`xs is [var first, ..]`, `parts is [var key, var value]`), `ElementAtOrDefault`, or check first. These checks count: `i < xs.Length`, `xs.Length > 2` (for `xs[2]` or less), `xs.Count == 3`, `xs.Any()` or `!xs.IsEmpty` (for `xs[0]` and `xs[^1]`), a list pattern or length pattern on the same list (`xs is [_, _, ..]`, `box is { Items.Length: > 0 } b` then `b.Items[0]`), a switch arm's pattern, and an early exit earlier in the block (`if (words.Length < 3) return ...;`). An index that ranges over the list itself is fine too: `Enumerable.Range(0, xs.Length).Select(i => xs[i])`, `xs.Select((x, i) => ...)`. So is `[0]` or `[^1]` on the result of `string.Split` without `RemoveEmptyEntries`, which always has at least one item. Writes (`xs[i] = ...`) are FP0002's. Slices (`xs[1..]`) aren't checked yet. An indexer that implements a list's own indexer may forward to its list: throwing there is that contract.
- **A default `ImmutableArray`** (`default(ImmutableArray<T>)`, `new ImmutableArray<T>()`) throws on nearly every use. Use `ImmutableArray<T>.Empty` or `[]`.

One engine decides what counts as "checked first" for division, dictionary lookups and indexing alike: `?:` and `if` branches, `&&` and `||`, `!`, `is` patterns, switch arms and their `when`, and early exits. A check written another way (in a helper, or inside a LINQ query before the use) isn't seen: restructure so the check and the use are together, which a list pattern does best.

Calls that can't throw where they are aren't reported:
- The input rules it out: `xs.DefaultIfEmpty(0).Max()`, `g.First()` on a group, anything after `Append` or `Prepend`.
- The keys are already unique: groups keyed by their key, `xs.GroupBy(k).ToDictionary(g => g.Key, ...)` (or after `ToLookup`), and distinct items keyed by themselves, `xs.Distinct().ToDictionary(x => x, ...)`. After `DistinctBy(r => r.Sku)`, the key can also be the same selector, `r => r.Sku`. Any other key is reported: `xs.Distinct().ToDictionary(s => s.Length)` can still collide. A key comparer on the dictionary must be the one the items were made unique with, written the same way: `xs.GroupBy(k, comparer).ToImmutableDictionary(g => g.Key, ..., comparer)`. Groups and distinct items are followed through filtering, ordering and copying (`Where`, `OrderBy`, `ToImmutableArray`...) and through a local: `var bySku = rows.GroupBy(r => r.Sku).ToImmutableArray();` then `bySku.ToDictionary(g => g.Key, ...)`.
- A `ContainsKey` check guards it, in `?:`, `if`, `&&` or `||`: `d.ContainsKey(k) ? d[k] : 0`, `m.ContainsKey(k) ? m : m.Add(k, v)`. The dictionary and key must be written the same way in the check and the call.
- It's a search that runs until it finds something: `First(...)` over `Sequences.From(n)`, or `Enumerable.Range(1, int.MaxValue)`.

### What it doesn't cover

FP0015 targets exceptions used as control flow in domain logic: "not found", "empty", "bad input". It doesn't try to cover every throw, because nearly any code can throw: `checked` overflow, decimal overflow, a slice out of range, running out of memory. Two things cover most of the rest:
- Nullable checking is on and its warnings are errors (`FunctionalCore.props`), which removes `NullReferenceException`.
- Tests that feed parsers and command handlers random input and check nothing throws. The sample apps do this with a small seeded generator (`samples/TestSupport/Fuzz.cs`). It mutates valid examples, so the inputs get past the first check and reach the deeper code: about 12,000 inputs across the ledger, highlight reel and ray tracer parsers, in a few seconds.

## Why

An exception is a hidden exit. Every one of these was found in the sample apps' core code, shipped or nearly shipped, because nothing pointed at it. The safe forms return something you have to look at, and you can turn "missing" into an `Option` or a `Result`.

## Instead

Before:

```csharp
public static decimal Price(ImmutableDictionary<string, decimal> prices, string sku) => prices[sku];
```

After:

```csharp
public static Result<decimal> Price(ImmutableDictionary<string, decimal> prices, string sku) =>
    prices.TryGetValue(sku, out var price) ? price : new Error("unknown-sku", $"No price for {sku}");
```

Not covered: arithmetic overflow and slices. Prefer list patterns where they matter.

## Auto-fix

None. Each safe form needs a decision about what "missing" means.
