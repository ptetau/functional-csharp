# FP0012: Result of a pure call is ignored

Calling a method as a statement is reported when the method returns a new value instead of changing anything. That covers:
- Immutable collections (`ImmutableArray`, `ImmutableList`, `ImmutableDictionary` and the rest), but not their builders or `ImmutableInterlocked`.
- LINQ (`Enumerable` and `ImmutableArrayExtensions`).
- `string`.
- `DateTime`, `DateTimeOffset`, `TimeSpan`, `DateOnly` and `TimeOnly`.

## Why

`list.Add(x)` on an immutable list returns a new list and leaves `list` alone. As a statement it does nothing. This is the easiest mistake to make when moving from `List<T>` to immutable types, and the compiler doesn't catch it.

## Instead

Before:

```csharp
var tags = ImmutableArray<string>.Empty;
tags.Add("new");
due.AddDays(7);
```

After:

```csharp
var tags = ImmutableArray<string>.Empty.Add("new");
var extended = due.AddDays(7);
```

If you really don't need the result, discard it on purpose: `_ = set.Contains(x);`.

## Auto-fix

None. Only you know what the new value should be called and where it goes.
