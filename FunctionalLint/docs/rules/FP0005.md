# FP0005: Mutable collection types are not allowed

Creating `List<T>`, `Dictionary<,>`, `HashSet<T>`, `Queue<T>`, `Stack<T>`, `LinkedList<T>`, sorted and concurrent collections, or `StringBuilder` is reported. So are `ToList()`, `ToDictionary()` and `ToHashSet()`, and locals declared as `IList<T>`, `ICollection<T>`, `IDictionary<,>` or `ISet<T>`.

## Why

A mutable collection can change after you've handed it on. Immutable collections can't, so they're safe to share.

## Instead

Before:

```csharp
var ids = orders.Select(o => o.Id).ToList();
var lookup = new Dictionary<int, Order>();
```

After:

```csharp
var ids = orders.Select(o => o.Id).ToImmutableArray();
var lookup = orders.ToImmutableDictionary(o => o.Id);
ImmutableArray<int> small = [1, 2, 3];
```

Watch out: methods like `Add` on an immutable collection return a new collection. Use the result, or nothing happens. FP0012 catches it when you forget.

## Auto-fix

For locals declared as a mutable interface: `IList<T>` becomes `IReadOnlyList<T>`, and so on, as in FP0008.

Not for creating collections. Swapping in an immutable type could change what the code does, so the message tells you what to use instead.
