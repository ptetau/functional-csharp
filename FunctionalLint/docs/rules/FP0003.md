# FP0003: Mutable state is not allowed

Non-readonly fields, `set` accessors (including `private set`) and record structs that aren't `readonly` are reported.

## Why

If a type can't change, anyone can hold it and share it safely. That stops a whole class of "who changed this?" bugs.

## Instead

Before:

```csharp
public record Order
{
    private int _version;
    public string Name { get; set; }
}
public record struct Point(int X, int Y);
```

After:

```csharp
public record Order
{
    private readonly int _version;
    public string Name { get; init; }
}
public readonly record struct Point(int X, int Y);
```

## Auto-fix

Yes. Adds `readonly` to fields (replacing `volatile`), turns `set` into `init`, removes the setter of a static auto-property, and makes record structs `readonly`.

If code elsewhere still assigns the member, the compiler then points at it. That code needs a new value instead (see FP0002).
