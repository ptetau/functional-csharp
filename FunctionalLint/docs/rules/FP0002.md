# FP0002: Mutation is not allowed

Reassigning a variable, `+=`, `++`, `??=`, writing to an array element or property, and subscribing to events are reported. So are:
- passing an existing variable as `out` or `ref` (`int.TryParse(s, out n)`, `Interlocked.Increment(ref n)`): use `out var n` instead;
- library calls that change their argument in place: `Array.Fill`, `Array.Sort`, `Array.Reverse`, `Array.Clear`, `Array.Copy`, `Span<T>.Fill` and friends;
- writing into an array or buffer that already exists: `CopyTo` into an array, span or memory (`src.CopyTo(dst, 0)`, `items.CopyTo(dst)`, `text.AsSpan().CopyTo(chars)`), `array.SetValue(x, i)`, `Buffer.BlockCopy` and `Buffer.SetByte`;
- `ImmutableCollectionsMarshal.AsImmutableArray`, which wraps an array its owner can still change.

Changes inside a loop are left to FP0001, which reports the loop.

## Why

When nothing changes after it's created, you can read any line without tracking what ran before it.

## Instead

Give the new value a new name, or build a changed copy with `with`.

Before:

```csharp
var price = basePrice;
price = price * 1.15m;
order.Status = Status.Paid;
```

After:

```csharp
var withTax = basePrice * 1.15m;
var paid = order with { Status = Status.Paid };
```

Still allowed:
- Object initialisers, `with` and anonymous objects, because they build a new value.
- Deconstruction into new variables and discards.
- Constructors, `init` accessors and static constructors setting their own type's members.
- Assigning an `out` parameter, so `TryParse`-style methods work.

## Auto-fix

None. The fix depends on how the value is used afterwards.
