# FP0019: Only the functional subset of C#

A core is written in a subset of C#. [`Subset.cs`](../../src/FunctionalLint/Subset.cs) lists the kinds of syntax it may use: records, unions, structs, interfaces and enums; methods, properties and operators; expressions, lambdas, patterns, switch expressions, collection expressions, `with`, `yield` and LINQ query syntax. Everything else is reported, including features a future C# adds: they're outside the subset until someone reviews them and adds them to the list. A few kinds are reported by other rules instead, with better advice: loops (FP0001), assignment (FP0002), setters (FP0003), classes (FP0004) and `throw` (FP0007).

Outside the subset:

| Feature | Why | Instead |
|---|---|---|
| `lock`, `volatile` | A core has no shared state to guard | Move it to a shell project |
| `try`, `catch`, `finally` | Exceptions aren't control flow in a core | Return a `Result` |
| `using` (statement or declaration) | Disposing is a side effect | Move it to a shell project |
| `event` | An event is a mutable list of handlers | Return the new state |
| `unsafe`, pointers, `fixed`, `sizeof`, `stackalloc`, `extern` | Raw memory and native code | Arrays and immutable collections; native calls in a shell project |
| `ref` locals and returns, `out` and `ref` parameters | Code that changes a value in place | Return a new value: a tuple, an `Option` or a `Result` |
| `async`, `await` | Async is for I/O, which is the shell's job | Take the result as a parameter |
| `checked` | It throws on overflow | A wider type, or check the range first |
| `!` (including `default!`) | It hides a possible null | Handle the null: a pattern, `??`, or an `Option` |
| `dynamic` | It turns off type checking | A real type, or a closed record for the cases |
| `object` as a type | It hides the type, so using the value needs a cast | The real type, a generic type parameter, or a closed record for the cases |
| `virtual` and `abstract` members | A subtype picks what runs, out of sight | A switch over a closed record's cases, or a function passed in |
| `abstract` types | Anyone can add a subtype, so a switch over it can't be checked | Mark it `closed` |
| Deriving from a record that isn't `closed` | Anyone can add a case, so a switch over the base can't be checked | Mark the base `closed` |
| Top-level statements | A program's entry point is the shell | Move it to a shell project |

Adapters and legacy namespaces are exempt. So are `async`, `out`, `ref` and `object` where a library's contract requires them in a signature: an override such as `Equals(object? obj)`, or an interface implementation such as `IReadOnlyDictionary.TryGetValue`. The interface's own declaration is still reported, if it's yours. Interfaces may declare `static abstract` members (generic math): that's a contract, not dispatch to hidden code.

### Kept on purpose

Two features look imperative but stay in the subset:
- **`yield`**. An iterator's state lives in a compiler-made object nobody can reach, so a `yield` method with a pure body is a pure, lazy sequence. It's the plain way to write one without a mutable list. (Loops inside it are still FP0001's.)
- **`unchecked`**. Wrapping arithmetic never throws, so it's total, and it's what hashing and seeded random number generators need. It's also C#'s default; writing it only says so. `checked`, which throws, is outside.

The project owner can allow more in the policy: `functional_lint.allowed_syntax = lock, try`. The names are the ones in the messages, or Roslyn's syntax kind names.

## Why

Rules that forbid known problems let everything else through: every feature nobody thought of. An allowlist works the other way round. The subset is written down in one place, so you can review it, and a core can't drift outside it.

## Instead

Before:

```csharp
public static bool TryPrice(string sku, out decimal price)
{
    try { price = Prices.Lookup(sku); return true; }
    catch (KeyNotFoundException) { price = 0; return false; }
}
```

After:

```csharp
public static Option<decimal> Price(ImmutableDictionary<string, decimal> prices, string sku) =>
    prices.TryGetValue(sku, out var price) ? Option.Some(price) : Option.None<decimal>();
```

(Calling `TryGetValue` with `out var` is fine: it's declaring an out parameter that's outside the subset.)
