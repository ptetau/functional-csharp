# FP0018: Functional cores reference only allowed libraries

When `functional_lint.allowed_references` is set (by `functionallint.policy`), a core may reference only the .NET base library (the `Microsoft.NETCore.App` reference pack) and the assemblies it lists. An entry ending in `*` allows a family, such as `Acme.Domain.*`. `none` allows the base library only. When the key isn't set, nothing is checked.

The base library is the `Microsoft.NETCore.App` pack, or `NETStandard.Library` for a netstandard project. ASP.NET Core and Windows Desktop are not part of it, and neither are Microsoft's NuGet packages, such as Entity Framework or `Microsoft.Extensions.Logging`.

## Why

FP0011 catches side effects from a list of known APIs, but every new library adds more. A core that can't reference a database client, logger or HTTP library can't call one, so the list is closed instead of open-ended.

## Instead

Keep the core to domain logic, and move the code that needs the library to a shell project, which passes the results in.

Before:

```csharp
// Shop.Core references Microsoft.EntityFrameworkCore
public static decimal Total(ShopContext db, string orderId) =>
    db.Lines.Where(l => l.OrderId == orderId).Sum(l => l.Price);
```

After:

```csharp
// Shop.Core: the shell loads the lines and passes them in
public static decimal Total(IReadOnlyList<Line> lines) => lines.Sum(l => l.Price);
```

## Auto-fix

None. Moving code between projects is a design change.
