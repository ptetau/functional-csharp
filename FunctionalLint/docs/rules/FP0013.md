# FP0013: Switches must stay exhaustive

Reported over an enum, a C# 15 `closed` type or a C# 15 `union`:
- A catch-all arm in a switch expression: one that matches every value, with no guard or a guard that's always true. That's `_`, `var x`, `{ }`, `not null`, `_ when true`, and a type every case has: the input's own type, one of its base types or interfaces (`object`, `Enum`, `IComparable`), or for a union, a type all its cases share. An `or` pattern with such a side counts too.
- A switch statement.
- Switching on a cast to a type the compiler can't check: `(object)shape switch { ... }`, `(int)colour switch { ... }`. Switch on `shape` or `colour` itself.

`[Flags]` enums, open hierarchies and types like `int` or `string` are fine: their cases can't all be listed.

## Why

C# 15 checks that a switch expression over these types handles every case. Add a new case and every switch that doesn't handle it becomes a compile error (CS8509, an error under FunctionalCore.props). That's the main reason to model choices as closed types or unions.

A catch-all arm quietly handles the new case, so nothing tells you to look. A switch statement is never checked at all.

## Instead

Before:

```csharp
public closed record Payment;
public sealed record Card(string Last4) : Payment;
public sealed record Cash : Payment;

public static string Describe(Payment p) => p switch
{
    Card c => $"card ending {c.Last4}",
    _ => "cash",
};
```

After:

```csharp
public static string Describe(Payment p) => p switch
{
    Card c => $"card ending {c.Last4}",
    Cash => "cash",
};
```

Add `sealed record Voucher : Payment` later and `Describe` stops compiling until it says what a voucher looks like.

## Auto-fix

None. Only you know what each case should do.
