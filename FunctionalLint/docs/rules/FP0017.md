# FP0017: Adapters only where the policy allows them

`[ImperativeAdapter]` switches every rule off for what it marks. When `functional_lint.adapter_namespaces` is set (by `functionallint.policy`), an adapter in a core must be in one of those namespaces or their sub-namespaces. `none` means a core may have no adapters at all. When the key isn't set, adapters may go anywhere, as before.

## Why

Without a limit, marking any method `[ImperativeAdapter]` silences every check on it, and nothing says that happened. Keeping adapters in a few named places makes them easy to find and review, and keeps the rest of the core pure.

## Instead

Pass the value in, so the function stays pure. Where an adapter really is needed, put it in an adapter namespace, or in a shell project (the host, CLI or web app), which isn't linted.

Before:

```csharp
namespace Shop.Pricing;

public static class Prices
{
    [ImperativeAdapter]
    public static bool IsOverdue(Invoice invoice) => invoice.Due < DateTime.UtcNow;
}
```

After:

```csharp
namespace Shop.Pricing;

public static class Prices
{
    public static bool IsOverdue(Invoice invoice, DateTime now) => invoice.Due < now;
}
```

## Auto-fix

None. Whether to pass the value in or move the adapter is a design choice.
