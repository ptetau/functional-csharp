# FP0011: Side-effecting API

Reading the clock, `Guid.NewGuid`, `Guid.CreateVersion7`, `Random`, `Path.GetTempFileName`, `Path.GetRandomFileName`, the console, `Debug` and `Trace`, files, `HttpClient`, processes, `Stopwatch`, `Thread.Sleep` and `Task.Delay` are reported as having side effects. So is the network below `HttpClient`: `Dns`, `Socket`, `TcpClient`, `TcpListener`, `UdpClient`, `WebRequest`, `WebClient`, `HttpListener`, `SmtpClient` and `Ping`. Pure `System.Net` types such as `IPAddress`, `WebUtility` and `HttpStatusCode` are fine.

The environment, `CultureInfo.CurrentCulture`, `TimeZoneInfo.Local`, `Path.GetFullPath`, `Path.GetTempPath`, `Dns.GetHostName` and `NetworkInterface` are reported as depending on the machine. Parallel LINQ (`AsParallel`) and `Parallel` are reported because they run work in an unpredictable order: summing doubles in parallel can give different bytes on each run.

Reflection that reads or runs a member chosen at run time is reported too, because the compiler can't see what it reaches: `typeof(DateTime).GetProperty("Now")!.GetValue(null)` reads the clock. That's `PropertyInfo.GetValue` and `SetValue`, `FieldInfo.GetValue` and `SetValue`, `MethodInfo.Invoke` and `CreateDelegate`, `ConstructorInfo.Invoke`, `MethodInvoker`, `ConstructorInvoker`, `Type.InvokeMember`, `Delegate.DynamicInvoke` and `Activator`. Looking members up (`typeof(T).GetProperty("Name")`, `GetMethods()`) and reading their names is fine.

Add more with `functional_lint.impure_apis`.

Hidden uses of `Environment.NewLine` are reported too, since they make output `\r\n` on Windows and `\n` elsewhere:
- indented writer options that don't set the newline: `JsonSerializerOptions { WriteIndented = true }` and `JsonWriterOptions { Indented = true }` without `NewLine`, and `XmlWriterSettings { Indent = true }` without `NewLineChars`;
- `text.ReplaceLineEndings()` with no argument.

## Why

A function that reads the clock or the disk can give a different answer for the same input. That makes it hard to test and hard to reason about.

## Instead

Pass the value in, or wrap the API in an adapter.

Before:

```csharp
public static bool IsOverdue(Invoice invoice) => invoice.Due < DateTime.UtcNow;
```

After:

```csharp
public static bool IsOverdue(Invoice invoice, DateTime now) => invoice.Due < now;
```

## Auto-fix

Only for the line-ending cases: the fix adds `NewLine = "\n"` (or `NewLineChars`) after the indent setting, and passes `"\n"` to `ReplaceLineEndings()`. Nothing else, since where a value should come from is a design choice.
