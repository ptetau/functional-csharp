# FP0022: Floating-point numbers aren't compared exactly

Reported on `==` and `!=` between two `double`, `float` or `Half` values, unless one side is a whole-number constant, and on any comparison with `NaN`.

Comparing with a whole-number constant is allowed: `x == 0`, `scale != 1`. That tests for a value that was set, not one that was computed, and whole numbers are exact in binary. A fraction such as `0.1`, or `0.1 + 0.2`, isn't exact, so comparing with it is reported.

## Why

Rounding makes floating-point results that should be equal differ slightly: `0.1 + 0.2 == 0.3` is false. Two computed values compared with `==` then depend on the order the arithmetic ran in, so a refactor that changes nothing can change the answer. `NaN` never equals anything, itself included, so `x == double.NaN` is always false.

## Instead

Before:

```csharp
public static bool SameLength(Vec3 a, Vec3 b) => a.Length == b.Length;
public static bool Missing(double x) => x == double.NaN;
```

After:

```csharp
public static bool SameLength(Vec3 a, Vec3 b) => Math.Abs(a.Length - b.Length) < 1e-9;
public static bool Missing(double x) => double.IsNaN(x);
```

For money and other amounts that must be exact, use `decimal`: it isn't reported.

Records with `double` fields still compare their fields exactly in their generated `Equals`. That's not reported: compare such records within a tolerance where it matters.

## Auto-fix

None. The right tolerance depends on the values.
