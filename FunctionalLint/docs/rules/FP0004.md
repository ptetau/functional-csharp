# FP0004: Classes are not allowed

Plain classes are reported. Records, static classes, structs, interfaces, enums, delegates and attribute classes are fine. So are plug-ins: classes that extend a library's abstract class, such as a Roslyn `DiagnosticAnalyzer` or a `JsonConverter<T>`, because the library needs a subclass. FP0003 still checks their fields. A class that extends your own abstract class is still reported.

## Why

A class bundles data with the methods that change it. Keeping data (records) apart from functions (static classes) makes both easier to test and reuse.

## Instead

Before:

```csharp
public class Order
{
    public int Id { get; set; }
}

public class Pricing
{
    public static decimal Total(Order order) => ...;
}
```

After:

```csharp
public record Order
{
    public int Id { get; init; }
}

public static class Pricing
{
    public static decimal Total(Order order) => ...;
}
```

## Auto-fix

Yes, when it's safe:
- A class with only static members becomes a `static class`.
- Any other class becomes a `record`, keeping its members.

It leaves a class alone if it has a primary constructor (a record would make the parameters public), inherits from another class, overrides `Equals(object)`, or is `partial`.

Code that needs a real class, such as an exception or a framework base class, belongs in an `[ImperativeAdapter]`.
