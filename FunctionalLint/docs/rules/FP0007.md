# FP0007: Throwing is not allowed

`throw` statements, `throw` expressions and rethrows are reported. So are library calls that exist to throw:
- the `ThrowIf...` helpers on exception types: `ArgumentNullException.ThrowIfNull`, `ArgumentException.ThrowIfNullOrEmpty`, `ArgumentOutOfRangeException.ThrowIfNegative`, `ObjectDisposedException.ThrowIf` and the rest;
- `ExceptionDispatchInfo.Throw(e)` and `ExceptionDispatchInfo.Capture(e).Throw()`.

## Why

An exception is a hidden exit from a function: nothing in the signature says it can happen. Returning a result puts failure in the signature, so callers must handle it.

## Instead

Before:

```csharp
public static Order Find(ImmutableArray<Order> orders, int id) =>
    orders.FirstOrDefault(o => o.Id == id) ?? throw new KeyNotFoundException();
```

After:

```csharp
public static Result<Order> Find(ImmutableArray<Order> orders, int id) =>
    orders.FirstOrDefault(o => o.Id == id) is { } order
        ? order
        : new Error("not-found", $"No order {id}");
```

`Result<T>` here is the closed record from [`samples/Functional`](../../../samples/Functional): a value or an `Error` converts to it implicitly, and callers switch over `Result<Order>.Ok` and `Result<Order>.Failed`.

Catch exceptions from libraries in an `[ImperativeAdapter]` and turn them into results there.

`ThrowIfNull` checks are rarely needed in a core: nullable checking is on, so a parameter that can't be null is typed without `?`.
