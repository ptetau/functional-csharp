# FP0014: Records must not hold collections that compare by reference

A record property or field whose type is a collection is reported, unless the type compares by contents: `ImmutableArray<T>`, arrays, `ImmutableList<T>`, `IReadOnlyList<T>`, dictionaries and the rest all compare by reference. Strings are fine, and so is any type marked `[ValueEquality]`, such as `ValueList<T>` from [`samples/Functional`](../../../samples/Functional). Records that write their own `Equals` are left alone.

## Why

A record promises value equality. But `ImmutableArray<T>.Equals` compares the underlying array reference, so a record holding one is never equal to a copy of itself:

```csharp
new Order("a", ["x"]) == new Order("a", ["x"])   // false
```

Nothing warns you. In the sample apps this failed 8 to 17 tests per app on first run, each printing two identical-looking values as "different". In real code it quietly breaks comparisons, dictionary keys and caching.

## Instead

Before:

```csharp
public sealed record Order(string Id, ImmutableArray<string> Tags);
```

After:

```csharp
public sealed record Order(string Id, ValueList<string> Tags);
```

`ValueList<T>` converts to and from `ImmutableArray<T>`, works with collection expressions (`Order("a", ["x"])`), and treats `default` as empty.

To use your own value-equal collection, mark it `[ValueEquality]`. FunctionalLint matches the attribute by name, like `[ImperativeAdapter]`.

## Auto-fix

None. Switching to `ValueList<T>` is usually a type-name change, but the type comes from your own library.
