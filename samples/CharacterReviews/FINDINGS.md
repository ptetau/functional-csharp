# CharacterReviews: findings

## Summary

- **Core size:** 769 lines in 8 files (`Model`, `Text`, `Validation`, `Forms`, `Queries`, `Library`, `Html`, `Site`). The web shell is 145 lines (`Program.cs`, `Store.cs`). 76 tests: unit tests on the core plus end-to-end HTTP tests.
- **Lint errors in the real code: 6**, all in the first draft of `Text.cs`: FP0001 x2, FP0002 x2, FP0005 x2. Every later file was clean on its first check. I had read `AGENTS.md` and the rule docs first and wrote in the functional style from the start, so the lint mostly confirmed what I already did. It didn't teach me much.
- **Lint errors in a deliberate probe file** (`Probe.cs`, about 20 things an agent might plausibly write, deleted afterwards): 11. FP0002 x4, FP0005 x2, FP0008 x2, FP0011 x2, FP0012 x1. At least 12 other real problems in the same file got through (rows 1–5 below).
- **Auto-fixed: 0** in the real code. In the probe, heal reported 3 fixes (FP0005 x1, FP0008 x2). One of those fixes broke the build (row 6), and the FP0005 "fix" was really a side effect of that broken FP0008 edit.
- **The worst miss was a compiler warning, not a lint rule.** `heal.sh --check` said "Clean" while the code had CS8907, which here meant infinite recursion (row 7).
- **Check time:** heal reports 4.5–5.5 s per check on this project. `heal.sh` takes 6.3–7.9 s wall clock, because it goes through `dotnet run` each time. The hook (`claude-code-hook.sh`, prebuilt dll) takes 5.0 s. That's fine once per file edit, but it's the main cost of the loop.

## What worked well

- **The rule set matches how I'd write this app anyway.** Records for data, static classes of functions, LINQ, `with`, and `ImmutableArray.Add` returning a new state made the state transitions (`State -> Validated<Added<T>>`) natural and easy to unit-test without a server.
- **FP0011 drew the core/shell line cleanly.** The clock (`TimeProvider`) and the file live in the web project, and `today` is a parameter. The core tests needed no fakes. The HTTP tests swap the clock with one line.
- **The messages for the errors I did hit were short, specific, and pointed at the right line.** FP0001's "LINQ, Aggregate or recursion" plus the rule doc table was enough to rewrite both loops in a minute.
- **FP0012 is a good safety net** for `ImmutableArray.Add` and LINQ. It's the mistake you make right after switching to immutable collections.
- **Switching on an enum without a discard arm works** (CS8524 off, CS8509 on). Adding a `TitleKind` would break `KindLabel` at compile time, which is what you want.
- **The hook's ~5 s budget is acceptable** for a per-edit check, and the exit codes make it easy to use as a "done?" gate.
