# Ledger: findings

Built by an agent (Claude) from `specs/ledger.md`, with `heal.sh --check` run after every core file was written or changed, as the per-edit hook would.

## Summary

- **Core size:** 415 lines of code in `Ledger.Core` (8 files, not counting blank and comment lines). The Cli is 17 lines. 68 tests, all passing, including a test that runs the real executable on the spec's examples.
- **Lint errors hit while building:** 1 in total. CS8509 x1 (a `switch` over the `Command` union). **No FunctionalLint (FP) errors at all.** I read `agents/AGENTS.md` and the rule docs first and wrote to them from the start, so the lint was a safety net that never fired.
- **Auto-fixed:** 0 in the app, because nothing was ever marked `[auto-fixable]`. To test the fixer anyway, I ran it on a throwaway copy of a typical OO first draft (outside the repo). It reported 17 problems, 15 marked fixable. The summary said 16 were fixed, but one of those "fixes" was a new compile error (#3).
- **Probe:** a throwaway file of 21 things an agent might plausibly write (deleted afterwards). The lint caught 5 of them (FP0002 x1, FP0011 x2, FP0012 x2) and missed about 15 (#5 to #10).
- **Check time:** `heal.sh --check` reports 4.4 to 5.3 s, but takes 6.2 to 7.7 s wall clock (10 runs). The hook script, which runs the built dll directly, takes 4.7 s. A no-op `dotnet build` of the core takes 1.5 s.
- **Bugs the lint couldn't see, found by reasoning or by tests:** decimal overflow crashing `Sum` (#7), output depending on the machine's culture (#8, avoided by habit), and an off-by-one in "which lines are new" when the journal has no trailing newline.

## What worked well

- AGENTS.md plus the rule docs were enough to write clean code first time. Every core file passed its first check except the CS8509 case, which the shared FINDINGS already warned about.
- No I/O in the core meant a 17-line Cli, and every command (including `add`/`open` refusing to change the file) is tested without touching the disk. `Outcome` says what to append, and the shell does it.
- List patterns over `ImmutableArray` (`[var name, var value, .. var rest] when ...`) made the argument parser short, recursive and exhaustive.
- `record` + `with` + `Aggregate` handled the parser's grouping state cleanly.
- `add`/`open` are validated by appending to the text and running the same validator: one code path for check, add and open.
- heal's `[auto-fixable]` marks and "Next time:" habits are well judged; the FP0003 and FP0008 signature fixes were correct apart from #3 and #4.
